## ¿Qué significa pasar de "Prompts" a "Loops"?
Hasta ahora, la relación con la IA ha sido lineal e iterativa a mano: tú escribes un prompt, la IA te responde, revisas el código, detectas un fallo, y escribes otro prompt para corregirlo. [1, 7] 
El enfoque de Loop Engineering automatiza por completo esa interacción mediante sistemas autónomos (o agentes): [2, 3, 7, 8, 9] 

* El Prompt Tradicional: Una instrucción estática. Input -> Respuesta -> Fin.
* El Loop: Un sistema de control continuo. Tú le das un objetivo final (un /goal). El sistema ejecuta el código, lo prueba de forma autónoma, lee los errores de la consola, se auto-corrige y repite el proceso en un bucle cerrado hasta que el objetivo se cumple perfectamente. [1, 3, 7, 10, 11] 

[Tu Objetivo] ➔ ┌─── [El Loop Automático] ───┐
                │ 1. IA genera el código     │
                │ 2. Ejecuta tests del sistema│ ➔ [Código Perfecto Listo]
                │ 3. Analiza los errores     │
                └─────── ⟲ Reintenta ────────┘

## Las claves del nuevo flujo de trabajo
Según los detalles compartidos por el equipo de Anthropic, un bucle de producción eficiente no es solo "dejar a la IA libre", sino estructurar el entorno con los siguientes pilares: [9, 12] 

   1. La meta final (/goal): Se define un estado final claro (ej. "Todos los tests de autenticación deben pasar en verde y sin advertencias"). [11] 
   2. Puertas de verificación independientes: El loop no se fía de la IA que escribe el código. Utiliza un evaluador independiente (como una suite de tests automatizados o un linter) para juzgar objetivamente si el resultado es correcto. [9, 11, 12] 
   3. Frenos de emergencia incorporados: Los bucles consumen miles de tokens rápidamente. Es obligatorio programar límites estrictos (ej. "Máximo 30 iteraciones o $10 de presupuesto") para evitar que un bucle infinito dispare la factura de la API. [11, 13]
