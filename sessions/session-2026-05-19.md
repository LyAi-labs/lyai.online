## Estudio UX de los chips del chat

**Los 6 chips actuales (turista)**:

| Chip | Frecuencia esperada | Valor real |
|---|---|---|
| ¿Dónde hay sol? | Baja-media | Útil pero muy específico · sólo aplica si hace mal tiempo |
| Reservar clase | Media | Útil familias / principiantes · audiencia minoritaria del PdS |
| Estado pistas | **Alta** | Top query de un esquiador (¿qué está abierto?) |
| Restaurants | **Alta** | Una de las 3 queries más frecuentes |
| Hotels | Media-baja | Búsqueda pre-viaje · cuando ya estás en el dominio raramente |
| Pharmacie | Muy baja | Emergencia ocasional |

**Lo que falta** según el comportamiento típico en una app de concierge alpino:

1. **"Alquilar material"** — falta. Es la TOP query del primer día del esquiador.
2. **"¿Dónde nieva mejor?"** — comparativa entre estaciones. Muy alpina y útil.
3. **"Llegar / Transporte"** — cómo llegar, navettes. Falta totalmente.
4. **"Webcams"** — checkpoint visual rápido.
5. **"Eventos hoy"** — qué pasa esta noche.

**Lo que sobra** (o podría refactorizarse):

- **Pharmacie**: muy específico para emergencia · mejor en un menú "Urgencias" separado
- **¿Dónde hay sol?**: query muy específica · mejor agrupar como subset de "Condiciones meteorológicas"

Cada owner registrado obtiene un QR personal que abre directo:

- El backend genera token JWT con `{owner_id, entity_ids[], exp}` corto-vivo
