## Lessons & feedback

### Multi-agente sobre mismo checkout · git race

Al hacer rebase tras los pushes del agente paralelo, mi commit dock+ChatTabIcon
inicial (`a0d99d7`) llegó a origin/main con diff vacío · solo el commit message
sobrevivió. El componente ChatTabIcon.tsx estaba creado pero no referenciado
desde _layout.tsx (un push paralelo lo dejó así). Detectado por user en
screenshot · re-aplicado completo en commit `35aebbb` (de Aurelio).

**Mitigación adoptada en mi sesión post-incidente**: `commit + push` encadenados
sin tareas intermedias para minimizar ventana de race. Funcionó para todos mis
commits siguientes.

### Catalog drift inevitable con índice estático

El `dev-xplain/index.html` mantenido a mano funciona mientras hay UN solo
agente. Con multi-agente + mockups creados en rápida sucesión, el drift es
garantizado. Auto-generator desde meta.json elimina el problema · regla a
respetar: agente que crea mockup crea su meta.json + corre build_catalog
antes de push.

### OpenTimestamps requiere ~1h de espera real

El `ots stamp` deja el `.ots` "pending" · los calendarios agrupan stamps de
muchos usuarios y emiten 1 tx Bitcoin por ventana ~hora. `ots upgrade` solo
descarga el merkle proof completo · NO acelera la confirmación. Para
verificación independiente sin Bitcoin node local: usar `--esplora=https://blockstream.info/api`
o checar la tx en mempool.space directamente.
