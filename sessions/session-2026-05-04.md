## 1. Override del frontend (gana sobre todo)

Si el cliente envía `lang` en el body del POST, se respeta y no se detecta. Solo soporta `es / fr / en`.

## 2. Hard markers (instantáneo → ES)

```python
_ES_HARD_MARKERS = ("¿","¡","ñ","Ñ")

```
Estos caracteres no existen en FR ni EN, así que cualquier `¿dónde…?` o `mañana` fuerza ES inmediatamente.

## 3. Palabras-bandera ES + langdetect (heurística)
```python
_ES_HARD_WORDS = {qué, dónde, cuándo, cómo, cuál, recomiendas,
                  restaurantes, hotel, hoteles, dame, quiero, puedo,
                  está, están, muy, mucho, ahora, comer, ver}
```
Cuenta cuántas aparecen en el texto, luego llama a la lib `langdetect` (basada en bigramas):

| `langdetect` dice | Resultado |
|---|---|
| `es / ca / gl` | ES |
| `en` | EN |
| `fr` | FR — pero si hay ≥1 palabra ES → ES (override) |
| `it / de / pt / …` | ES si hay palabra ES, si no FR |
| (excepción / no instalado) | ES si hay palabra ES, si no FR |

## 4. Default
- Texto < 3 caracteres → FR.
- Cualquier otro caso ambiguo → FR (público objetivo PdS = mayoría francófona).
