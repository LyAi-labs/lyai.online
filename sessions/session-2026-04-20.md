## Cómo funciona el Route Calculator

**Es un grafo de red de pistas + remontes con algoritmo Dijkstra** (el mismo que usa Google Maps, pero para esquiar).

### Arquitectura en 3 capas

**1. Carga de datos (al abrir el calculador)**
```
API → getPistes() + getLifts() para cada estación del PdS
    → Construye nodos (puntos) y aristas (conexiones)
```

**2. El grafo**
- Cada **remonte** = arista dirigida de abajo → arriba (duración: `duration_min` de la BD)
- Cada **pista** = arista dirigida de arriba → abajo (duración estimada por dificultad + `length_km`)
- **Transiciones** = conexiones automáticas entre nodos próximos en altitud (<500m diferencia)

**3. Cálculo (al pulsar "Calculer")**
- Dijkstra clásico: encuentra el camino de **menor tiempo** entre las dos estaciones
- El resultado muestra cada paso: 🚠 remonte / ⛷️ pista / 🚶 transición + minutos

---

### El problema actual (verano)

En verano **todas las pistas y remontes están cerradas** (`status: 'closed'`). El grafo asigna coste `Infinity` a los nodos cerrados → Dijkstra no encuentra ruta → devuelve "No route found".

Por eso en el chat, cuando `open_lifts_count = 0`, se redirige a transporte SBB en vez del route calculator.

---

### No hay interacción con el mapa

El calculador es **completamente independiente del mapa visual**. Solo seleccionas estación de origen y destino en los desplegables. El mapa de la pestaña "Carte" muestra pistas/remontes en tiempo real pero no está conectado al calculador (sería una mejora futura — pinchar en el mapa para elegir origen/destino).
