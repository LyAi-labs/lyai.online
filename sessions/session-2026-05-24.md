## Qué significa "servir imágenes"

**Situación actual**:
- Los `.jpg` están en disco: `/opt/lyai/app/lyai-ski-static/dev-feedback/ignacio_20260524_033959_0.jpg`
- Solo accesibles si haces SSH al server y miras el filesystem
- Desde un navegador (`https://dev.lyai.pro/dev-feedback/xxx.jpg`) → **404 Not Found** porque nadie le ha dicho a Traefik/nginx que esa carpeta del disco se exponga al mundo

**"Servir"** = configurar el router (Traefik) para que cuando llegue un GET a `https://dev.lyai.pro/dev-feedback/*.jpg`, lea el archivo de `/opt/lyai/app/lyai-ski-static/dev-feedback/` y lo devuelva como respuesta HTTP. Mismo concepto que el `/app/index.html` (sirve archivos de `/var/www/dev.lyai.pro/app/`).

## Por qué importa para la inbox

Si quieres una página `https://dev.lyai.pro/feedback-inbox.html` que liste los feedback con thumbnails:

```html
<!-- En el HTML de la inbox -->
<img src="/dev-feedback/ignacio_20260524_033959_0.jpg" />
```

Para que esa `<img>` se renderice en el navegador:
- El navegador hace GET `https://dev.lyai.pro/dev-feedback/ignacio_20260524_033959_0.jpg`
- Traefik debe mapear `/dev-feedback/*` → carpeta del disco
- **Sin ese mapping, el `<img>` queda roto** (icono de imagen rota)

## Trade-offs

| | Pro | Con |
|---|---|---|
| **Servir public** (cualquiera con URL ve el .jpg) | Setup trivial · 5 líneas en routes.yml · thumbnails funcionan directo | Privacy nula · capturas tuyas accesibles si alguien adivina el nombre (`ignacio_YYYYMMDD_HHMMSS_0.jpg` es predecible) |
| **Servir con auth bearer** (header `Authorization`) | Privadas · solo tú con token | Más curro · necesita middleware Traefik + token guardado en localStorage del browser |
| **Servir con basic auth** (popup user/pass) | Privadas · 1 línea más en config | Popup login cada sesión nueva · UX feo |
| **NO servir · convertir a base64 en JSON** | Sin nuevo endpoint · todo embebido en respuesta `/api/feedback-inbox` | Channel crece (base64 = +33% tamaño) · imágenes en RAM al cargar inbox |

## Mi recomendación

Como las capturas son **dev feedback tuyo personal** (no contenido público de la app), iría con **basic auth simple** (1 user/pass guardado en .env del Traefik · popup login solo la primera vez por sesión). O incluso más simple: servir con un token en la query string (`?t=secret`).
